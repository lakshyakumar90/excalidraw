# Prompt for the Phase 18 implementing agent

Implement Phase 18, the hand-drawn renderer, end to end. Read `docs/phase-18-hand-drawn-renderer-agent-instructions.md` completely and inspect the referenced source and applicable `AGENTS.md` files before editing. The handoff is the specification. Do not start another phase.

Extend the existing renderer: it already has seeded polyline jitter, hatch fills, rounded corners, persisted style fields, culling and dirty static rendering. Replace duplicated Canvas/SVG jitter with shared deterministic numeric path commands. Implement seeded independent random streams, double Bézier strokes, overshooting sharp rectangles/diamonds, smooth double ellipses, tangent rounded corners, explicit intersection-clipped hachure, perpendicular cross-hatch and closed solid fill. Map Architect/Artist/Cartoonist to existing roughness 0/1/2 without adding a competing schema. Preserve dashes, opacity, rotation, curved arrows, bindings, text gaps, pressure freedraw, text and images.

Keep algorithms and caches in `packages/engine`, browser/server contracts in `packages/common`, and UI/lifecycle changes in `apps/web`. Keep DB/auth/server responsibilities intact. Reuse existing geometry, styles, previews and export callers. Render randomness must be determined by element.seed; pan, zoom, DPR, cache order and unrelated element order must never reroll the shape.

Add a bounded geometry cache and per-element OffscreenCanvas/HTML-canvas bitmap cache. Include ID, version, versionNonce, zoom bucket, DPR and visual dependencies in invalidation. Handle in-progress local/remote geometry changes without version bumps by bypassing committed caches or using bounded transient identities. Cull before building geometry or bitmaps, include decorative paint bounds, cap memory/pixel sizes, evict and dispose resources, and provide oversized-shape fallback. Canvas/SVG exports must share geometry; high-resolution PNG must not reuse low-resolution screen bitmaps.

Implement the focused test matrix in the handoff: deterministic streams and commands, shape/ellipse/rounded edge cases, clipping intersections, style/opacity/transform behavior, arrow regressions, cache invalidation and bounds, same-version previews, culling, and exports. Run the affected renderer suites in nonwatch mode and relevant type checks; run one production web build, one short visual journey and one two-browser preview/commit/viewer journey. Diagnose failures or stalled commands; rerun only the affected checks. Avoid repeated broad suites.

Create a deterministic 5,000-element development stress scene and measure cold/warm rendering, culling, panning, zoom bucket changes, preview churn and DPR. Record actual render-time median/p95, allocations, cache hits/misses/evictions and retained bytes on identified hardware/browser. Profile before optimization; do not claim 60 FPS from animation-loop counters or invent benchmark results.

Commit and push small coherent implementation steps with their tests, preserving existing edits. Record final decisions and real verification/benchmark results in `docs/architecture/phase-18-decisions.md`. At completion, run/reuse the full web/HTTP/WS/flush-worker stack and existing Redis, leave it available for manual testing, and report completed features, limitations, checks, benchmark figures, commit IDs, branch and URLs. Do not claim completion based only on planning, type checks or health endpoints.
