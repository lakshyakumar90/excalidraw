# Step 1.2 — Distributed `seenMutations`, Deep `/health`, and Flush Concurrency

## Summary of Improvements
Hardened multi-replica WebSocket/HTTP idempotency, replaced shallow `/health` endpoints with deep Postgres + Redis dependency probes, and scaled the snapshot flush worker with per-room Redis locking.

## Key Changes
1. **Distributed Mutation Idempotency (`packages/redis/src/index.ts`, `packages/backend-common/src/collaboration.ts`)**:
   - Added `claimMutation` (`SET collab:mut:<sceneId>:<mutationId> 1 EX 300 NX`), `getMutationResult`, and `storeMutationResult` to `RoomRedis`.
   - Updated `applyCommit` to check and persist mutation idempotency in Redis across replicas, falling back cleanly to the in-process `seenMutations` `Map` if Redis is temporarily unreachable.
2. **Deep `/health` Probes (`packages/db/src/prisma/db.ts`, `packages/redis/src/index.ts`, `apps/http-server/src/app.ts`, `apps/ws-server/src/server.ts`)**:
   - Added `pingDatabase(2000)` (`SELECT 1` with 2s timeout) and `RoomRedis.ping(2000)` (`PING` with 2s timeout).
   - Updated `GET /health` in both `http-server` and `ws-server` to probe Postgres and Redis in parallel, returning `200` when healthy and `503` (`status: "degraded"`) if either dependency fails.
3. **Parallel Flush Worker + Per-Room Redis Lock (`apps/flush-worker/src/index.ts`, `packages/redis/src/index.ts`)**:
   - Raised BullMQ worker concurrency from `1` to `8` (configurable via `FLUSH_WORKER_CONCURRENCY`).
   - Added `acquireFlushLock` (`SET lock:flush:<sceneId> <token> PX 15000 NX`) and atomic Lua `releaseFlushLock` inside `startWorker` so multiple rooms flush concurrently while the same room never races itself.
4. **Redis AOF Persistence**:
   - Confirmed `compose.yaml` and `compose.ec2.yaml` run Redis with `--appendonly yes --appendfsync everysec` to minimize write-behind data loss on restart.
