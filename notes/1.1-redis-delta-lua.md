# Step 1.1 — O(k) Delta Patch Lua CAS in Redis

## Summary of Improvements
Eliminated the $O(N)$ full-hash delete-and-rewrite bottleneck in `packages/redis/src/index.ts` and connected `packages/backend-common/src/collaboration.ts` to send only changed and deleted elements on every commit.

## Key Changes
1. **Delta Lua CAS (`packages/redis/src/index.ts`)**:
   - Introduced `SnapshotDelta` (`{ changedElements: Record<string, unknown>; deletedIds?: string[] }`).
   - Replaced the full-hash wipe-and-rewrite Lua script in `writeSnapshot` with `WRITE_SNAPSHOT_LUA`, which validates `__version == expectedRevision`, applies `HSET` only for `changedElements` and `HDEL` only for `deletedIds`, updates `__version` and `__meta`, and marks `collab:dirty-rooms`.
   - Retained full-replace fallback when `delta` is omitted (e.g., cold cache seed).
   - Replaced hot-path `HGETALL` calls in `writeSnapshot`, `scheduleFlush`, and `leave` with $O(1)$ `HMGET` metadata-only reads (`readSnapshotMeta`).
2. **Minimal Delta Computation (`packages/backend-common/src/collaboration.ts`)**:
   - Added `computeElementDelta(previousElements, nextElements)` after deterministic LWW merge (`reconcileElements`) and tombstone pruning so `applyCommit` sends only modified/added elements and pruned element IDs.
   - Updated `attachFile` to emit an empty element delta (`{ changedElements: {}, deletedIds: [] }`), making file attachment $O(1)$ in Redis.
3. **Benchmark & Correctness Tests (`packages/redis/src/index.test.ts`)**:
   - Added a 5,000-element room test verifying that patching 1 changed element and deleting 1 element executes the Lua CAS in `< 2 ms` while leaving unchanged keys untouched.
